# Build Throughline

최종 원고 작성 전, 하나의 질문을 오래 탐색할 수 있는 구조와 필요한 원재료 확보.

## 참조 문서

- 구조 파일 생성·갱신 전 `references/worksheet-schema.md` 전체 읽기
- `작성 준비 완료` 판정 전 `references/readiness-gate.md` 전체 읽기

## 책임 경계

- 개인 회고와 기술 에세이의 구조 설계
- 핵심 질문 후보 비교와 추천
- 논리적 빈칸 확인과 순차 인터뷰
- 별도 structure 파일 생성·점진적 갱신
- 최종 산문, 제목, 설명, 문체 작성 금지
- OU 개인 문체·사고 프로필 적용 금지
- 확정 구조의 실제 원고화는 `ou-writing`에 인계

## 1. 원재료 수집

사용자가 지정한 파일, 붙여 넣은 메모, 현재 대화의 글감을 모두 확인.

- 파일로 확인 가능한 사실을 다시 질문하지 않기
- 각 항목을 `사실·장면`, `사용자 판단`, `외부 주장`, `추정`, `확인 필요`로 구분
- 기존 초안의 매끄러운 연결을 사실로 오인하지 않기
- 경험, 감정, 동기, 성과 임의 생성 금지
- 입력 원문 수정 금지

## 2. 핵심 질문 선택

서로 다른 답을 요구하는 주제가 둘 이상이면 핵심 질문 후보 2~3개 제시.

각 후보에 다음 정보 포함:

- 질문 한 문장
- 글의 긴장 또는 모순
- 사용할 수 있는 원재료
- 가장 큰 빈칸
- 선택 시 보류할 재료
- 추천 여부와 근거

추천 시 원재료 밀도, 생각의 충돌, 개인적 이해관계, 결론의 비자명성, 사건 결속력 기준 사용. 최종 선택은 사용자에게 맡기고 한 번에 하나의 결정만 질문. 선택 전 structure 파일 생성 금지.

사용자가 핵심 질문을 이미 명시한 경우에도 원재료가 실제로 그 질문을 지지하는지 짧게 검증. 별도 선택이 불필요하면 바로 구조 설계 진행.

## 3. 임시 구조 생성

선택된 질문을 기준으로 `references/worksheet-schema.md`의 고정 항목과 가변 구간 적용.

경로 규칙:

1. 사용자가 지정한 출력 경로
2. 입력 파일 slug를 사용한 `content/drafts/<slug>.structure.md`
3. 파일 입력이 없으면 대화에서 짧은 kebab-case slug 추론 후 동일 경로 사용

입력 파일명 끝의 `.add`, `.star`, `.notes`, `.draft`, `.structure`는 작업 단계 suffix로 보고 제거. 예: `essay.add.md` → `essay.structure.md`.

구조 파일 상태를 `탐색 중`으로 시작. 모든 사건에 다음 역할 중 하나 부여:

- 질문의 출발점
- 임시 답의 근거
- 임시 답을 복잡하게 만드는 사례
- 반대 해석의 근거
- 관점이 달라진 전환점
- 현재 질문과 무관한 보류 재료

개인 경험과 기술 주장은 하나의 핵심 질문을 함께 검토할 때만 혼합. 서로 다른 결론을 요구하면 분리 제안 후 현재 선택 밖의 재료를 `보류 재료 / 별도 글 후보`에 기록. 별도 글 파일 자동 생성 금지.

## 4. 핵심 빈칸 인터뷰

임시 구조에서 글 전체를 성립시키는 가장 상위 의존성 하나 선택.

- 한 번에 질문 하나만 제시하고 답변 대기
- 현재 구조와 질문 이유를 한두 문장으로 설명
- 구조 선택 질문에는 추천과 근거 제공
- 경험·감정·동기 질문에는 답 추정이나 추천 금지
- 사용자가 막힌 경우 이미 제공한 표현만 선택지로 재구성
- 답변 반영 후 structure 파일 갱신
- 다음 빈칸은 직전 답변에 의존하는 순서로 선택
- 모든 빈칸을 한꺼번에 나열해 작성 부담을 넘기지 않기

## 5. 기존 구조 갱신

기존 structure 파일 전체를 읽고 사용자가 작성한 문장과 답변 보존.

- 사용자 작성 내용 삭제·요약·윤문 금지
- 새 원재료는 출처와 역할을 구분해 추가
- 충돌하는 답변은 덮어쓰지 않고 `충돌 / 재검토`로 병기
- 구조 변경 시 구간 역할과 우선순위만 갱신
- 더 이상 사용하지 않는 재료는 삭제 대신 보류 구간으로 이동
- 기존 핵심 질문 변경은 사용자 확인 후 적용

## 6. 준비도 판정과 인계

인터뷰 갱신마다 준비도 표를 사실대로 갱신. `references/readiness-gate.md`의 필수 조건을 모두 충족하기 전 상태를 `작성 준비 완료`로 변경하지 않기.

준비 완료 시에만 `원고 작성 인계` 블록 생성:

- 확정 핵심 질문
- 잠정적인 답
- 구간별 역할과 사용할 근거
- 의도적으로 남긴 불확실성
- 보류·분리한 재료
- 과장하거나 임의 생성하면 안 되는 지점

인계 블록 생성 후에도 최종 원고 작성 금지. 사용자에게 structure 경로와 준비도만 보고하고 `ou-writing` 사용 가능 상태 안내.

## 완료 기준

- 원문과 structure 파일 분리
- 사용자 작성 내용 보존
- 모든 구간의 핵심 질문 기여도 확인
- 핵심 연결의 사용자 근거 확보
- 임시 답과 반대 해석 공존
- 보류 재료의 제외 이유 기록
- 준비도 상태의 근거 일치
