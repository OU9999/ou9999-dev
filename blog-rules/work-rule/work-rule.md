# Work Rule

작업 진행·검증 규칙. 성공 기준 정의 후 검증될 때까지 반복. 사소한 작업은 판단껏 축소.

## 목표 정의

- 모호한 요청을 검증 가능한 목표로 변환
  - 버그 수정 → 재현 경로 확보 + 수정 후 해소 확인
  - 리팩터링 → 변경 전후 동작 동일 확인
  - 문서·규칙 정리 → 참조 경로와 중복 제거 확인
- 멀티스텝 작업은 간단한 계획과 단계별 검증 항목 명시
- 사용자가 명시하지 않은 운영 작업은 최소 범위로 제한

## 진행 원칙

- 작업 전 `git status --short --branch` 확인
- 기존 사용자 변경 보존
- 불필요한 리팩터링·메타데이터 변경 금지
- 외부 서비스 상태 변경 전 목적과 영향 범위 확인
- PR 생성·재오픈·merge는 사용자 명시 지시 전까지 금지

## 검증 기준

- 기본 코드 변경 → `npm run lint`
- 빌드·라우팅·콘텐츠 생성 영향 → `npm run build`
- UI·브라우저 동작 영향 → Playwright 또는 실제 브라우저 확인
- 스킬·규칙 문서 변경 → 해당 validator 또는 `git diff --check`
